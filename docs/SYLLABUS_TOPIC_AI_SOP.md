# Syllabus 与知识点分类的 AI 复核 SOP

适用于 CAIE AS & A Level 新科目、已有四科迁移或大纲改版。统一目标是**执行时官方科目页已发布的最新完整 syllabus，连同 update**；历史真题也只收录符合该版学习目标的题。脚本负责下载、PDF 验真、文字提取和结构校验；当 PDF 排版使规则解析不可靠时，AI 根据**已下载的官方 syllabus PDF**制作草稿。所有草稿先进入待复核区，不直接覆盖正式 `topics_<code>.json` 或既有 `tags_<code>/`。

## 输入

1. 科目代码、官方科目页 URL、目标真题年份及最新已发布 syllabus/update PDF 路径；须记录 PDF SHA-256 和官方标注的适用年份。目标真题年份允许早于最新 syllabus 的首考年。
2. 旧版 `topics_<code>.json`（如有）及版本差异；新科目可无。
3. 分类阶段再提供每卷完整 `*_qp.json`、必要的原卷 PDF/裁图和经核准的知识点 JSON；不要仅用截断的 500 字符摘要判复杂题。

## 阶段一：生成知识点大纲草稿

可直接交给 AI 的提示词：

> 阅读官方科目页，先确认当前已发布的最新完整 syllabus 版本及 update；再阅读本地对应 PDF 的“Subject content/Assessment”相关页。按原有章节顺序提取章号、章名、小节号、小节名、Paper/AS/A2 对应关系。每项给出 PDF 页码和原文短证据；不要依据常识补全 PDF 中没有的章节。输出与仓库 `topics_<code>.json` 兼容的草稿 JSON：`subject,name,zh,source,note,levels,sections[{code,en,zh,subs[{code,en,zh,kw}]}]`。`kw` 为有限、可从大纲原文或明确同义词支持的英文短语列表。另输出 `evidence.json`（每个 code 对应文件名、PDF 页码、证据）和 `review.md`（不确定项、相较旧版的学习目标变化、编号变化、删除/新增章节）。旧版大纲只用于识别变化与迁移，不作为正式收录标准。不要覆盖正式文件。

校验：JSON 可解析；科目代码匹配；章/小节代码唯一且顺序与 PDF 一致；`levels.papers` 与官方 assessment 表一致；章节数、标题、页码逐项能回到 PDF；中文仅为辅助说明，不替代英文原文。抽查每章至少一个小节和全部编号边界，处理 update 的修改条目。未通过则保留草稿状态。

## 阶段二：试切与分类

先选 3–5 份跨年份/Paper/版式的 QP 试切，逐题检查题号、小问、共享题干、图表、页码和官方 MS。扫描件或切题失败卷标记待 OCR/待修，不编造题目。

可直接交给 AI 的分类提示词：

> 读取已核准的最新 `topics_<code>.json`、官方 syllabus 学习目标原文、该卷全部单元全文及必要的 QP 原页。对每个单元 ID 先判 `IN/OUT/PENDING`：确实考查最新大纲学习目标才为 `IN`，并输出 1–3 个合法小节码（主码第一）及对应学习目标证据；确定考纲外为 `OUT` 并说明理由；证据不足为 `PENDING`，不得猜码。旧版标签只能作参考，章节编号相同也要核对内容。共享题干须结合全部小问；包含考纲外或待确认小问的完整大题不能进入模拟组卷。输出标签候选与独立的逐单元状态/复核报告，报告含原卷页码、依据及低置信项。既有 `tags_<code>/` 不直接覆盖；通过校验后由迁移/合并程序发布。

校验：卷内每个单元 ID 恰好一个 `IN/OUT/PENDING` 状态；`IN` 有至少一个合法 code、`OUT` 有原因、`PENDING` 有待核问题；没有多余 ID、空标签或非法 code。`OUT` 样本逐条复核；旧版标签迁移必须以实际学习目标对照，不作纯编号替换。随机抽查至少 20 道、覆盖实际存在的 MCQ 与结构题；所有低置信、跨版本和定位异常项单独复核。只有 `IN` 进入正式分类、知识点、搜题和组卷索引；通过后再运行合并、持久化、索引流程，并在运行报告保留抽检记录。
